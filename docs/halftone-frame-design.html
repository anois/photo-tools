半调网屏
新相框「半调网屏 Halftone」— 把照片降解成一张双色理索印刷品 frame: halftone · family: print · fx pipeline

参考 PS 的「灰度 → 位图半调网屏 → 邻近重采样 → 渐变映射」流程，在引擎里新增一个 作用于照片像素本身的 fx 钩子：油墨色、纸色、网点密度、颗粒粗细、网线角度、网点形状、明暗全部 是用户可拨的 cfg 旋钮，并顺手引入全局「无相框模式」——只导出风格化后的图片本体。 上方横幅就是本稿内嵌原型的实时渲染。

SIG.01参考解析 · PS 流程 → 引擎映射

PS 的六步，引擎的一趟像素循环

教程里的六步操作本质上是三次变换：去色（灰度）、网屏二值化（位图 + 半调网屏， 频率 / 角度 / 形状三参数）、双色映射（渐变映射把黑白染成油墨色和纸色）。中间那步 「分辨率改 72 → 邻近重采样回原尺寸」制造的是颗粒感——低分辨率下算出的网点被整像素放大， 边缘保持硬邻近锯齿。这四件事在 Canvas 里就是一次降采样、一趟 ImageData 循环、一次关闭平滑的放大回绘。

SIG.04引擎架构 · frame.fx 钩子

第一个作用于照片像素的帧钩子

引擎现有两个帧钩子都不碰照片本体：decorate 在照片周围画装饰，clipPath 改照片轮廓。 半调需要第三类能力——重写照片像素。新增 frame.fx(ctx, layout, params, args)， 在前景（单图或拼图 cells）绘制完成后、caption 之前调用，双端镜像（clientRender.js + worker.js，同 decorate 的纪律）：

bg → fg shadow → fg photo / collage cells → ★ frame.fx ← 半调在这里发生：读回 fg envelope 像素 → 网屏化 → 回写 → caption SVG → topTemplate 徽标 → frame.decorate → 用户印章 seal 文字 / 徽标 / 装饰 / 印章全部落在网屏之后 —— 保持实色锐利（参考海报的行为）

作用域：fg envelope，而非整幅画布

fx 只处理前景包络矩形（拼图时含 12px 沟槽——沟槽是纸色，亮度高，网屏化后仍是纸色，视觉无损）。 不处理纸边距：米黄纸色亮度约 0.92，若整幅处理，每个网格中心都会冒出一粒墨点， 整圈边距布满杂点。fg-only 让边距永远干净，而照片高光→裸纸的映射依然与边距无缝（两者就是同一个颜色）。

分辨率无关性：预览 = 导出，逐像素一致

网格与颗粒都定义在 base-1440 单位上：画布像素下 cellPx = htCell × scale、chunkPx = htPx × scale， 于是工作缓冲尺寸 fgW / chunkPx = fgW_base / htPx —— 与渲染倍率无关。 0.5× 预览和 2.7× 高清导出算出的是同一张工作位图，只是邻近放大的倍数不同。半调帧的预览不是近似，是精确的。 

// frames/halftone.js — fx 参考实现（试印台跑的就是这份逻辑）
function fxHalftone(ctx, layout, params, args) {
  const p = params.halftone;
  const r = { x: layout.fgLeft, y: layout.fgTop, w: layout.fgW, h: layout.fgH };
  const chunk = Math.max(1, p.px * layout.scale);          // 颗粒的画布像素尺寸
  const workW = Math.max(8, Math.round(r.w / chunk));
  const workH = Math.max(8, Math.round(r.h / chunk));
  const work = (typeof OffscreenCanvas !== 'undefined')      // worker 恒有；老 Safari 主线程回退
    ? new OffscreenCanvas(workW, workH)
    : Object.assign(document.createElement('canvas'), { width: workW, height: workH });
  const wctx = work.getContext('2d', { willReadFrequently: true });
  wctx.drawImage(ctx.canvas, r.x, r.y, r.w, r.h, 0, 0, workW, workH);   // 降采样读回

  const img = wctx.getImageData(0, 0, workW, workH), d = img.data;
  const cell = Math.max(1.5, p.cell / p.px);                // 工作分辨率下的网格边长
  const rad = p.angle * Math.PI / 180, cs = Math.cos(rad), sn = Math.sin(rad);
  const g = Math.pow(2, -p.tone);
  const [ir, ig, ib] = hexRgb(p.ink), [pr, pg, pb] = hexRgb(p.paper);
  for (let y = 0, i = 0; y < workH; y++) for (let x = 0; x < workW; x++, i += 4) {
    let l = (0.2126*d[i] + 0.7152*d[i+1] + 0.0722*d[i+2]) / 255;
    l = Math.pow(l, g);
    const u = (x*cs + y*sn) / cell, v = (-x*sn + y*cs) / cell;      // 旋转网格坐标
    const fu = u - Math.floor(u) - 0.5, fv = v - Math.floor(v) - 0.5;
    const on = l < spot(fu, fv, p.shape);                            // 网屏阈值二值化
    d[i] = on ? ir : pr;  d[i+1] = on ? ig : pg;  d[i+2] = on ? ib : pb;  d[i+3] = 255;
  }
  wctx.putImageData(img, 0, 0);
  ctx.save();
  ctx.imageSmoothingEnabled = false;                          // PS「邻近（硬边缘）」
  ctx.drawImage(work, r.x, r.y, r.w, r.h);
  ctx.restore();
}

// spot 函数：PS 网点形状的阈值场。格角处 t→0，纯黑也留纸色角点（理索暗部呼吸感）
function spot(fu, fv, shape) {
  switch (shape) {
    case 'round':   return 1 - Math.hypot(fu, fv) * 1.4142;
    case 'line':    return 1 - Math.abs(fv) * 2;
    case 'diamond': return 1 - (Math.abs(fu) + Math.abs(fv));
    default:        return 1 - Math.min(Math.abs(fu), Math.abs(fv)) * 2;  // cross 十字线
  }
}

SIG.05无相框模式 · cfg.frameless

只要那张纸上的图

「只转化图片样式」做成全局旋钮而不是半调专属——cfg.frameless 对任何帧都成立 （画布 = 照片本体，跳过一切帧化妆），只是在效果帧上才真正有趣。这符合「引擎旋钮尽量全局化」的产品方向， 成本是走一遍非挂载 cfg 字段的 11 触点清单（一次性）。

维度frameless = true 的行为
画布比例 = 照片有效比例（裁切 + 旋转后），实现上直接把 effW+':'+effH 喂给现成的 resolveAspectPreset 动态合成——短边 1440 × quality 的现行规则不变，几乎零新布局代码
跳过padding（四边归 0）、caption、topTemplate 徽标、decorate、clipPath、阴影、圆角（归 0）；bg 被照片全覆盖
保留frame.fx（这就是本模式的意义）、印章 seal（水印场景成立）、crop / rotation / collage（拼图保留沟槽、去外边距，包络比例沿用 cfg.aspect）
持久性切帧不重置——它是「我要什么产物」而非「帧调多少」，语义上与 aspect 同类，而非 bg*/shadow* 那类帧栓参数
UI 位置工作台 ┃ Caliper 顶部一个开关「无边框 · 仅照片」；开启时 aspect seg / padding / caption 相关控件加 .inert 淡化（可见但明示不生效），Notation 顶部一行提示
EXIF / 导出不变——照常走 reattachExif；对非效果帧，frameless 导出 ≈ 重编码原图（与 RAW 按钮的区别：吃 crop / rotation / collage / seal）
 
// buildLayoutAndCaption（clientRender.js / worker.js 双端镜像）：
if (cfg.frameless) {
  layoutOpts.aspect = effW + ':' + effH;      // resolveAspectPreset 动态合成，短边 1440 规则不变
  layoutOpts.paddingTop = layoutOpts.paddingRight = layoutOpts.paddingBottom = layoutOpts.paddingLeft = 0;
  layoutOpts.captionHeight = 0;  layoutOpts.radiusOverride = 0;
  // caption / topBadge SVG 不构建；compose() 跳过 shadow / decorate / clipPath；fx 与 seal 照常
}

边界与风险

  • 老 Safari 主线程无 OffscreenCanvas — fx 内回退 document.createElement('canvas')（worker 路径恒有 OffscreenCanvas，无需回退）。
  • getImageData 读回 — 工作画布用 willReadFrequently: true 建上下文，避免 Chrome 反复 GPU→CPU 迁移告警。
  • 旋转照片不旋转网屏 — fx 在 fg 绘制之后作用于画布像素，网线角度只由 htAngle 决定（与 PS 拼合后处理一致），这是特性不是 bug，文档写明。
  • customBg 无效 — 本帧 bg 为 solid，行为与其他 solid 帧一致，仪器卡不出 customBg 区。
  • smoke 基线 — 新帧不改旧帧路径；fx 调用点有 typeof frame.fx === 'function' guard，旧帧零开销。
  • 出厂 preset — 旋钮先行落地（本次），P2 可加 riso-poster seed（halftone + topTemplate: wordmark），符合「先旋钮后种子」设计规则。
SIG.08裁决点 · 待你拍板

四个开放决定（各附推荐）

Q1 · 效果作用域

fx 只处理照片区域，还是整幅画布？

整幅 = PS 拼合流程的字面复刻，但米黄纸边会在每个网格中心冒墨点，整圈边距长杂点。

推荐：fg envelope。边距永远干净；照片高光→裸纸与边距本就同色，无缝效果不受影响。
Q2 · frameless 归属

全局 cfg 旋钮（Caliper），还是半调专属开关？

专属开关实现最省（挂进 frame.cfg 即可），但「只要照片本体」对任何帧都是合法诉求。

推荐：全局 cfg.frameless。一次性付清 11 触点成本，换引擎级能力；切帧不重置。
Q3 · caption 上墨

说明文字要不要染成油墨色？

参考海报的文字就是油墨色。但 caption 颜色目前由 textStyle: light/dark 二值决定，改动面在 caption 系统。

推荐：v1 用现有 dark。米黄纸上深灰字成立；「caption 染 ink」记为 P2 独立旋钮（对所有帧有意义）。
Q4 · 默认网点形状

cross 十字线还是 round 圆点？

教程与参考海报用十字线（细密网格感）；经典理索/报纸印刷是圆点（颗粒感更「点」）。
