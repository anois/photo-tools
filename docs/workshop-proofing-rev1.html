photo-tools · workshop · interaction proposal · rev.1

灯下看样

「调参数时图像变化不明显」的病根不在渲染管线 —— 管线是实时的。病根在于调参的那一刻，画面正被自己的工作台遮住：移动端的底部抽屉盖掉 92% 视口，预览只剩约 20px；桌面端画布虽然还在，却被一层 50% 黑 + 4px 模糊的全屏遮罩蒙着。

暗房里没有人盯着旋钮打光 —— 调放大机的时候，眼睛始终在相纸上。这份草案提出一个原则和四个机制：印相期间，暗房让位给相纸。

§ 01

诊断 — 反馈去哪儿了

先给证据。以下四条全部来自当前代码（行号为 2026-08-19 refactor/workshop-darkroom 分支），不是感觉。

证据 E1 · 移动端
调参时预览画布可见高度 ≈ 20px，等于不可见

工作台是 92dvh 的底部抽屉（styles.css:4454），顶边落在视口 8dvh 处；canvas pane 从 topbar 44px 以下开始。两者相减，露出来的画布约 20px——还压着全屏遮罩。

主力用户在手机上出片（CLAUDE.md 规则 13），这意味着主力场景下每一次滑杆调整都是盲调。

证据 E2 · 桌面端
画布被 50% 黑 + 4px 模糊的遮罩压着

.workshop-overlay::before 是 inset:0 全屏遮罩：rgba(5,6,8,.5) + backdrop-filter:blur(4px)（styles.css:4118-4128）。抽屉本体只占右侧 440px，画布还有约 800px 宽可见 —— 但被压暗又打糊。

阴影模糊 60→70、背景饱和 1.0→1.1 这类变化本来就微妙，隔着暗玻璃看，等于没变。

证据 E3 · 渲染链路
26 个滑杆全部没有拖动态，每帧跑满清渲染

工作台全部 26 个滑杆都是裸链路：input → cfg → readout → requestRender()，每帧 PREVIEW_SCALE=0.5 满清渲染，约 50–80ms/帧（app.js:5673 注释自陈）。

而 Compose 模式早已解决过这个问题：拖动中降到 customScale 0.2（约 8–12ms/帧），松手 120ms 后 settle 一帧满清（app.js:6143-6155）。这套底座工作台一直没接。

证据 E4 · 既有对比能力失效
「看原图」功能在工作台打开时恰好双双失效

项目已有 peek 机制（enterPeek/exitPeek，app.js:2714-2740）：桌面按住空格、移动端长按画布看原图。但工作台打开时——桌面端焦点在滑杆 INPUT 上被守卫拦掉（app.js:2944），移动端画布被遮罩盖住摸不到。

最需要对比的时刻，对比恰好不可用。

桌面端现状 · 画布可见但整体压暗 + 模糊
topbar canvas 残余 ≈ 20px workshop sheet 92dvh

§ 02

主张 — 印相期间，暗房让位给相纸

工作台 1.12.1 的设计语言已经立了一条规矩：amber = 用户的手。这次把它延伸到画布上——手握住旋钮的瞬间，光应该落在被调整的画面上，而不是留在工作台里。三条推论：

P1
画布永远是第一反馈面

任何时刻、任何交互状态，预览画面不被压暗、不被模糊、不被完全遮挡。遮罩可以承担「点击空白关闭」的职责，但不再有视觉存在。这是结构性修复，不是交互糖。

P2
手在哪，光在哪

握住旋钮（pointerdown）的瞬间，工作台的 chrome 淡出退后，只留手指下的那一行控件；画面以全亮度呈现，读数以 HUD 形式浮在画布上。松手后工作台回场。调参的姿态从「在面板里改数字」变成「在灯下看着相纸拧旋钮」。

P3
变化要有地址

每个旋钮声明它影响画面的哪个区域（背景 / 阴影圈 / 字幕区 / 四角……）。握住旋钮时，画布上对应区域亮起一圈 amber 虚线描边——视线有落点，微妙的变化才看得见。渲染管线的 layout 矩形本来就算好了，只是从来没给用户看过。

§ 03

四个机制 + 一个底座

全部机制都建立在项目已有资产上——Compose 的低清拖动、HUD 气泡、peek 看原图都是现成范式，这次是把它们接进工作台，不是发明新轮子。

S0底座 · 性能
低清拖动渲染 — 让反馈先「跟手」

给全部工作台滑杆接入 Compose 同款拖动生命周期：pointerdown 进入 drag 态 → renderPreview 走 customScale 0.2（每帧 ~10ms，60fps 跟手）→ pointerup 后 120ms settle 一帧 0.5 满清。用一个委托绑定器挂在 bench 容器上（input[type=range] 事件委托），26 个滑杆零散改动一处都不用碰，未来新增旋钮自动继承。

这不只是性能优化——拖动跟手本身就是最基础的「变化可感」：画面以 60fps 连续响应手指，比任何静态高亮都更能传达因果。

A结构修复
遮罩退场 — 工作台不再是模态

桌面端：.workshop-overlay::before 对画布区域不再压暗、不再模糊。点击空白关闭的行为保留（透明层照样接收点击），但视觉上工作台成为「并排的工作面」而非「弹出的对话框」。画布在剩余空间里重新居中（canvas-stage 加一个 translateX 过渡，抽屉 440px 宽的一半），照片不再被抽屉切掉半边。

移动端此阶段不动结构（92dvh 密度是刻意选择），可见性交给机制 B 解决。

B拖动编排
关灯看样 — 握住旋钮，工作台退后

pointerdown 在任何滑杆上 60ms 后：工作台整体淡出到 ~5% 不透明度，只有手指下的那一行控件原地保持全亮（滑杆绝不能从手指下移走）；画布完整显现。松手后停留 240ms 再让工作台回场——留一拍让眼睛确认结果。

移动端是同一套编排的更强版本：sheet 背景转为近乎透明，画布从抽屉后面透出来（canvas pane 本来就在 sheet 下层原位渲染着，只是被盖住了——不需要移动任何东西）。这是移动端「盲调」问题的解，也是整个方案的签名交互。

键盘同理：焦点在滑杆上按方向键，首次 keydown 进入看样态，最后一次 keydown 600ms 后回场。

C视线引导
读数上画布 + 区域描边 — 变化有地址

看样态下，画布顶部浮出 HUD（复用 .compose-hud 的类族，seal-hud 已有先例）：参数名 + 当前值，amber 等宽字。同时，该旋钮声明的影响区域亮起一圈 1px amber 虚线（矩形来自渲染管线现成的 layout：fgRect / caption zone / canvas 边距……只需从 renderPreview 暴露最近一次 layout）。

「阴影模糊」描出照片下缘外圈，「字幕高度」描出字幕带，「背景饱和」描出照片以外的整个边框区——即使像素变化只有 3%，眼睛也知道往哪看。完整映射表见 § 05。

D对比
试印对比 ◐ — 「改完之后 vs 进门之前」

打开工作台时把当前预览画布拍一张「开台样张」（一个 ImageBitmap，成本可忽略）。bench 顶栏加一个 ◐ 钮：按住显示样张，松手回到当前状态——与既有 peek 完全同构（peek 对比的是原始照片，◐ 对比的是本次进工作台之前的成品，两者互补，都保留）。

顺手修两个既有 peek 的失效：桌面端焦点守卫放行 input[type=range]（空格对滑杆本无语义）；移动端在看样态下画布可触，长按 peek 恢复可用。

§ 06

实施注记 — 三个 PR，一次一个

沿用 rev2 的节奏：每个 Phase 独立可验收、独立进 CHANGELOG。全部复用既有范式，无新依赖、无 schema 变化（不触碰 cfg / preset / share-code）。

PR-1→ 1.13.0底座 + 退幕
S0 低清拖动 + A 遮罩退场

S0：bench 容器上委托绑定 pointerdown/up/cancel（range 输入），全局 benchDrag 状态 + settle timer 照抄 beginDrag/endDrag（app.js:6143-6155）；doRender 在 drag 态传 customScale: 0.2（renderPreview 的 clamp 入口现成，clientRender.js:613）。setPointerCapture 包 try/catch（既有 pitfall）。

A：.workshop-overlay::before 桌面端去掉 dim + blur（保留透明点击层）；body[data-workshop-open] .canvas-stage 加 translateX 重心过渡。纯 CSS + 一个 body class。

风险与既有坑位对照

  • pointercancel 必须与 pointerup 同权处理（iOS 手势打断），否则工作台卡在 5% 透明度——Compose 的 bindDrag 已处理，照抄。
  • 活动行绝不能在 LIVE 态移动：所有编排只做 opacity / background，不做 transform / 布局变化——滑杆从手指下移走是死罪。
  • opacity 不穿透父级上限：活动行嵌在仪器卡片等容器里时，给容器整体降 opacity 会连活动行一起压暗，子级设 opacity:1 也救不回来（本文档 mock 制作时实测踩中）。淡出必须结构化施加——活动行的祖先链整条保持可见，只淡出祖先链之外的兄弟节点（一次 closest() 链遍历即可）。
  • 遮罩退场后点击空白关闭的命中区不变：只改视觉，不改事件（overlay 点击处理在 app.js:4317）。
  • 描边层坐标换算要在 canvas CSS 尺寸变化（窗口 resize、低清/满清切换）时重算——低清态 canvas 像素数变了但 CSS 盒不变，换算基准用 CSS 盒。
  • 移动端 sheet 透明化后 lookbar 会透出来：LIVE 态 body class 顺带压暗 lookbar / topbar，视觉只留照片 + 活动行 + HUD。
  • 工作台滑杆样式选择器已有专门的特异性规则（.workshop--bench .x-slider 前缀，1.12.1 教训）——新增 .is-live 规则同样从组件根起链。
§ 07

留给 review 的决策点

以下问题不阻塞 PR-1（底座 + 退幕没有争议面），但影响 PR-2 / PR-3 的形态。每题附建议。

桌面遮罩要「彻底退场」还是留一层极轻的着色？

彻底退场 = 工作台从「模态对话框」降格为「并排工作面」，与 role="dialog" 的语义有轻微出入（可同步调整 aria）。留 8% 着色则保留一点「工作台在前」的层次感。

建议：彻底退场。画布是第一反馈面，8% 也是税。层次感由抽屉自身的边线和投影承担。

移动端 LIVE 态：sheet 整体透明化，还是下滑让位？

下滑让位（sheet 滑到只剩活动行）画面更完整，但滑杆会从手指下移走，拖动直接断掉——已否。透明化方案活动行原地不动，照片从 sheet 后面透出，代价是活动行会压住照片一角。

建议：透明化。活动行本身带半透明底 + 模糊，压住的一角仍隐约可见；真实照片区域受损极小。

离散控件（frame seg / toggle / 色板）要不要也「关灯」？

点击后自动关灯 1s 能让换 frame 的效果直接呈现，但误触成本高（每次点击都闪一场）。v1 草案只给离散控件做区域描边闪现（桌面），移动端不处理。

建议：v1 按草案收窄；上线后若「换色板看不到效果」被实际抱怨，再加可选的点击关灯。

◐ 试印样张的基线什么时候重拍？

候选：只在开台时拍（语义最清晰）/ 每次切 tool 重拍（粒度细但语义模糊）/ 手动重钉（双击 ◐）。

建议：开台拍 + 双击 ◐ 重钉，HUD 标注取样时间。切 tool 不重拍——「本次进工作台改了什么」是最自然的对比单位。

要不要做「试印条 test strip」？（远期）

暗房原教旨的对比方式：把当前参数扫出 N 档，在画布上分条并排渲染（如阴影模糊 0 / 40 / 80 / 120 四竖条），一眼选档。渲染成本 = N 次低清渲染，技术上可行，但 UI 面积、交互入口、与 LOOK 系统的关系都需要单独设计。

建议：不进本次三个 PR，作为远期概念挂起——先让「看得见」落地，再谈「看得多」。
